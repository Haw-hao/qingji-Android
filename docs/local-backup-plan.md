# 本地自动备份设计与执行计划（0.3.4）

用户已于 2026-10-22 确认方案：选择手机本地目录，每次数据变更自动备份；卸载后重装，重新授权相同目录并确认恢复。

## 设计

SQLite 仍为运行时数据源。通过 Android Storage Access Framework 获取用户选择目录的持久访问权限，将账单、账户初始余额和自定义分类写成独立 JSON 快照。每次数据变更在进程内的串行后台队列中备份，写完重新读取校验成功后才清理更旧的有效快照，始终保留新旧两份成功备份。备份文件含格式版本与 SHA-256 校验。

目录授权、最近备份时间及失败提示保存在应用设置；卸载后授权与设置消失，但共享目录中的文档保留。重装时用户重选目录，展示最新有效备份的日期、账单及账户数；只有确认恢复才用数据库事务替换数据。选择有备份的目录时禁止自动用空数据库覆盖，取消不启用新目录。恢复也标记旧演示数据迁移完成，防止旧迁移删除恢复数据。

分类从旧 SharedPreferences 一次性迁入 SQLite 的 local_app_state 表；账单、账户、分类及恢复后的迁移保护位在同一个 SQLite 事务中提交，避免跨存储提交中断。文件名逻辑时戳至少比既有最大合法文件名晚 1 毫秒，保证手机时钟回调时仍能选择最后成功写入的快照。

设置页提供选择目录、立即备份、从当前目录恢复、停用自动备份及状态展示。目录必须由用户在系统文件选择器中选择手机本地位置，例如 Documents/轻记备份。文件为明文，仅保存本地；不申请整盘管理权限，不接入云服务。不将通知去重状态和备份目录授权打包迁移。

若目录不可访问或磁盘已满，保留数据库与已有备份并显示错误；自动备份只保证已完成写入的数据，不能承诺突然断电前尚在队列中的更改已落盘。
